Syntax
Python provides four main keywords for handling exceptions: try, except, else and finally each plays a unique role. Let's see syntax:

try:
      # Code 
except SomeException:
      # Code 
else:
     # Code 
finally:
    # Code 

try: Runs the risky code that might cause an error.
except: Catches and handles the error if one occurs.
else: Executes only if no exception occurs in try.
finally: Runs regardless of what happens useful for cleanup tasks like closing files.
Exception Handling allows a program to handle unexpected errors during execution in a controlled way, instead of crashing abruptly. It enables programs to detect errors, manage them properly and continue execution wherever possible.

Handles runtime errors such as invalid input, file not found, division by zero and type mismatches that occur during program execution.
Helps improve program reliability by ensuring the application does not terminate unexpectedly when an error occurs.

2. When does each block execute?
Block	When it runs
try	Always starts first
except	When a matching error occurs in try
else	When try finishes without an error
finally	Almost always, regardless of the outcome

but what if there is on else option too?
Even if you add an else block, it will not execute when an error occurs in try, whether the error is caught or not.

try:
    print(10 / 0)

except ValueError:
    print("Caught ValueError")

else:
    print("Success!")

finally:
    print("Finally runs")

print("Program continues")

Output:

Finally runs
ZeroDivisionError: division by zero
Why?
try raises a ZeroDivisionError.

except ValueError doesn't catch it.

else is skipped because try failed.

finally executes.

The uncaught error propagates, so Program continues never prints.

Remember these three rules:

except → runs if a matching error occurs.

else → runs only if try finishes without an error.

finally → runs regardless of success or error in normal execution.

1. class GardenError(Exception):
Creates your own error named GardenError.
- Exception is Python's built-in parent class for errors.
- Inheriting from it makes GardenError a real Python exception that you can raise and catch.
2. def __init__(self, message="Unknown garden error"):
This initializes the error when you create it.
- self refers to this particular error object.
- message is the error message you want to display.
- "Unknown garden error" is the default if you don't provide a message.
Example:
raise GardenError("The garden is damaged!")



If you don't provide a message:
raise GardenError()



The message will be Unknown garden error.
3. super().__init__(message)
Calls the parent class (Exception) to initialize the exception with your message.
This allows Python to display the message when you catch and print the error:
try:    raise GardenError("The garden is damaged!")except GardenError as error:    print(error)



Output:
The garden is damaged!


Remember: __init__ sets up the error message, and super().__init__(message) passes that message to Python's built-in exception system.
